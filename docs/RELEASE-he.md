# מעבר מבדיקות לשימוש באייפון

הפיצ׳רים הבסיסיים הושלמו בקוד בגרסה 0.6.0. הפעולות הבאות דורשות חשבונות
בבעלות המפעיל, שירות ענן פעיל ומכשיר לבדיקה; הן לא בוצעו אוטומטית.

## 1. שירות הנתונים

- צרו פרויקט Supabase והפעילו אימות כתובת אימייל.
- הריצו את קובצי `supabase/migrations/` לפי הסדר 001–006. בפרויקט קיים
  מריצים רק קבצים שטרם הופעלו. שדרוג 006 מוסיף מסמכים ושדות חובה לחברות במרחב;
  עדכנו את שני הלקוחות לגרסה החדשה לפני בדיקות.
- הגדירו ב־`.env` את URL הפרויקט ואת המפתח הציבורי לפי `.env.example`.
  מפתח service-role נשאר בצד השרת בלבד.
- בתבנית Reset Password ב־Supabase הוסיפו את קוד השחזור `{{ .Token }}`:

```html
<h2>שחזור סיסמה — ביחד</h2>
<p>קוד השחזור שלכם הוא: {{ .Token }}</p>
<p>
  הזינו אותו במסך שחזור הסיסמה באפליקציה. אם לא ביקשתם שחזור, התעלמו מהמייל.
</p>
```

הגדירו SMTP אמיתי, תוקף קוד ומגבלות קצב. התהליך אינו דורש פתיחת קישור
באפליקציה. הגדרת קוד המייל נדרשת; אין להסתפק בתבנית שחזור עם קישור בלבד.

## 2. מסמכים פרטיים

```sh
npx supabase login
npx supabase functions deploy documents --project-ref YOUR_PROJECT_REF
```

משאירים את בדיקת JWT של השער פעילה. הפונקציה בודקת את טוקן הכניסה גם מול Auth ומוודאת חברות במרחב.
Supabase מספק לשרת את `SUPABASE_URL` ואת `SUPABASE_SERVICE_ROLE_KEY`.
הם אינם משתנים ציבוריים באפליקציה.

ודאו שה־bucket בשם `wedding-documents` פרטי. מותרת קריאה רק למסמך הרשום
במרחב של המשתמש. העלאה ומחיקה נעשות דרך הפונקציה; אין הרשאת כתיבה ישירה
ללקוח. הגבלות: PDF, JPEG ו־PNG, עד 5MiB, עד 100 מסמכים למרחב.
קישור פתיחה חתום תקף ל־60 שניות. גם שותף שעוזב עשוי להשתמש בקישור שכבר
נוצר עד שפג תוקפו. בדקו בלוגים אם נדרש ניקוי קובץ לאחר העלאה שלא נרשמה.

## 3. בדיקת שני חשבונות

הפעילו `npm run start:auth`, צרו שני חשבונות, אמתו את האימיילים והזמינו
שותף למרחב. בדקו את רשימת הקבלה ב־`ACCEPTANCE.md` מול הפרויקט האמיתי.
בדקו גם חשבון שלישי שאינו יכול לקרוא או לשנות מידע של הזוג.

שחזור סיסמה צריך לדרוש קוד מהאימייל, לעדכן סיסמה ולהחזיר לכניסה.
עזיבת אחד השותפים צריכה להשאיר את המידע אצל השני, בלי להחליף את הצד
שאליו משויכות המשימות. האחרון במרחב חייב למחוק מסמכים לפני עזיבה או
מחיקת חשבון. מחיקת חשבון מוחקת גם את משתמש Auth, ולא רק את החברות במרחב.

## 4. בנייה מחדש לאייפון

עדכנו ב־`app.json` את מזהה האפליקציה למזהה שבבעלותכם והגדירו ב־Expo
את שני משתני החיבור הציבוריים עבור סביבת הבנייה. פרופיל development
הקיים מתחבר למרחב פיתוח מקומי; לבדיקת חשבונות אמיתיים השתמשו ב־preview.

```sh
npx eas-cli@latest login
npx eas-cli@latest init
npx eas-cli@latest build --platform ios --profile preview
```

הבנייה וההתקנה דורשות Apple Developer והגדרת חתימה/מכשירים לפי הנחיות Expo.
בדקו במכשיר אמיתי שמירת התחברות לאחר סגירה, Face ID, בחירת ופתיחת קבצים,
צמצום תנועה בהגדרות הנגישות, והתראות בחזית, ברקע ובמסך נעול.
התראות הן מקומיות; שינויים מרחוק כשהאפליקציה סגורה מחייבים פתיחה לסנכרון.

## 5. TestFlight והפצה

לפני פרסום הגדירו במסך הפרטיות את שם המפעיל, כתובת תמיכה וכתובת מדיניות
פרטיות ציבורית. התאימו את הצהרות הפרטיות בחנות לנתונים ולספקים שבפועל
בשימוש. כעת המסך מציין שהגרסה בבדיקות ושפרטי התמיכה טרם הוגדרו.

```sh
npx eas-cli@latest build --platform ios --profile production
npx eas-cli@latest submit --platform ios --latest
```

הפיצו תחילה ב־TestFlight לשני בני הזוג. יצוא JavaScript והצלחת בדיקות
בדפדפן אינם אישור שבנייה חתומה, חתימת Apple או מסירה למכשיר הושלמו.
