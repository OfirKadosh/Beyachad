# הפעלת ביחד בווב ובאפליקציה

אותו repository ואותם חשבונות Supabase משמשים את שתי הפלטפורמות.
כל פיתוח חדש ייבדק בווב וב־iOS; מימושים נפרדים ליכולות מכשיר יהיו בקובצי
`.native.ts` לצד מימוש הדפדפן, ללא שכפול מסכים או לוגיקה עסקית.

## Render Static Site

1. חברו את GitHub ל־Render ובחרו New → Static Site → OfirKadosh/Beyachad.
2. Branch: main. Root Directory: ריק.
3. Build Command: `npm ci && node --import tsx scripts/check-config.mjs --production && npm run export:web`.
4. Publish Directory: `dist`.
5. הגדירו NODE_VERSION=22.15.0, EXPO_PUBLIC_APP_ENV=production,
   EXPO_PUBLIC_DEV_SESSION=false ואת שני משתני הלקוח מה־.env:
   EXPO_PUBLIC_SUPABASE_URL ו־EXPO_PUBLIC_SUPABASE_PUBLISHABLE_KEY.
   אין להגדיר DATABASE_URL או service_role/secret key באתר.
6. הוסיפו Rewrite מ־`/*` אל `/index.html` (לא Redirect), כדי שרענון מסך פנימי יעבוד.
7. בקובץ render.yaml נמצאות ההגדרות המקבילות לשימוש ב־Blueprint.

המשתנים משולבים בזמן הבנייה; שינוי שלהם דורש פריסה מחדש.
לא נדרש דומיין אישי. Render מספק HTTPS וכתובת onrender.com.
אין להריץ Metro או npm start באתר הייצור.

## התקנה באייפון

פתחו את כתובת ה־HTTPS ב־Safari, בחרו שיתוף → הוספה למסך הבית ופתחו מהאייקון.
היכנסו מתוך החלון שנפתח; אין להניח שסשן Safari יעבור לחלון המותקן.
ההתחברות נשמרת באחסון הדפדפן. במכשיר משותף יש לצאת מהחשבון.
ניקוי נתוני אתר או מגבלות אחסון עלולים לדרוש כניסה חוזרת.

## בדיקות קבלה לפני שימוש

- כניסה, רענון וסגירה מלאה ופתיחה מחדש מהאייקון.
- יציאה מהחשבון ופתיחה מחדש ללא גישה למרחב הקודם.
- סנכרון שינוי משימה בין דפדפן ל־Expo Go עם שני חשבונות האפליקציה.
- פתיחת קישור פנימי ישירות ורענון שלו.
- העלאה, פתיחה ומחיקה של תמונה ו־PDF באייפון.
- מקלדת, עברית, גלילה ותצוגה צרה; בדיקה חוזרת ב־Expo Go.

## מגבלות נוכחיות

אין מצב אופליין או service worker; נדרש אינטרנט לקריאה ולשמירה בענן.
ביומטריה והתראות מקומיות זמינות רק במימוש המכשיר המתאים, ולא בווב.
בווב קיימת רשימת התזכורות בתוך האפליקציה; Web Push אינו ממומש.
הוספה למסך הבית אינה הופכת את האתר לאפליקציית App Store.
שחזור במייל עדיין תלוי בהגדרות הדיוור שנדחו.

## מה נשאר לאחר העלאת הקוד

יצירת Static Site ב־Render היא פעולה נפרדת מהעלאת הקוד ל־GitHub.
לא הוזנו מפתחות לפרויקט Render ולא נפרס שירות מתוך סביבת הפיתוח.
לאחר פריסה מוצלחת יש לעדכן ב־Supabase את Site URL וכתובות החזרה המורשות
לכתובת האתר שבשליטתכם, לפני בדיקת אימות אימייל וקישורי שחזור.
אין צורך לשנות מיגרציות או לשכפל את מסד הנתונים עבור הווב.
